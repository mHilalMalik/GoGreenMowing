================================================================================
THE ONE THING THAT MATTERS MOST (ROOT CAUSE)
================================================================================
The site is a CLIENT-SIDE-RENDERED React/Vite SPA on Netlify that serves an
empty 1,638-byte shell to crawlers. Every URL — homepage, /services, /about,
all 5 blog posts, even fake 404 URLs — returns the BYTE-IDENTICAL empty page
with the same <title>. All content, headings, NAP, reviews, and schema only
appear AFTER JavaScript executes in a browser.

Proof:
  curl -A "GPTBot"    https://gogreenmowing.ca/         -> 1638 bytes, <div id="root"></div>
  curl -A "GPTBot"    https://gogreenmowing.ca/services -> 1638 bytes, IDENTICAL
  curl -A "ClaudeBot" https://gogreenmowing.ca/blog/... -> 1638 bytes, IDENTICAL

What this breaks, all at once:
  * AI crawlers see NOTHING. robots.txt explicitly invites GPTBot, ChatGPT-User,
    Google-Extended, PerplexityBot, ClaudeBot — but none execute JS. Red carpet
    to a glass door with an empty room. GEO score: 22/100.
  * Google indexes every page as the homepage until its delayed "second-wave"
    render runs (hours to weeks, not guaranteed). Bing largely can't render it.
  * LocalBusiness schema, NAP, and the 4.9-star rating are invisible to anything
    that doesn't run JavaScript.
  * Social shares (Slack, LinkedIn, iMessage) preview every page as the homepage.

>> Fixing rendering is the prerequisite for ~60% of everything else in this report.
   No content, schema, or copywriting fix matters until content reaches crawlers.

================================================================================

[1] SHIP SERVER-RENDERED / PRERENDERED HTML FOR ALL ROUTES
    Content is largely static (5 pages + 5 blog posts) — ideal for prerendering.
    Options by effort:
      LOW    - Prerender.io or Netlify bot-prerendering (serves snapshot to bots)
      MEDIUM - react-snap / vite-plugin-ssr build-time snapshot  [RECOMMENDED]
               (real static HTML per route, no runtime cost, robust)
      HIGH   - Migrate to Astro or Next.js SSG (near-zero JS, fixes CWV too, permanent)
    Verify: curl -A "GPTBot" https://gogreenmowing.ca/services | wc -c
            should jump from 1,638 bytes to several KB with real body text
            + <script type="application/ld+json"> present.

[2] MOVE JSON-LD SCHEMA INTO SERVER-RENDERED HTML
    curl finds ZERO application/ld+json today — schema is JS-injected. A bundle
    error, hash change, or crawler timeout silently kills all rich-result
    eligibility. Bake schema into initial HTML per route (folds into fix #1).

[3] REMOVE OR PROPERLY BACK THE AGGREGATERATING (4.9 / 120)
    Rating is HARDCODED in the JS bundle. Google requires aggregateRating to
    reflect genuine reviews VISIBLY on the page (or pulled live). A static,
    never-changing 4.9/120 with no on-page individual Review markup is a common
    trigger for a "review markup spam" MANUAL ACTION that can suppress rich
    results for the ENTIRE domain. Either display real reviews with Review items,
    pull live from GBP, or remove it until you do.

[4] RESOLVE NAP / PHONE CONSISTENCY & BRAND-CONFUSION RISK
    - Website uses ONE consistent number: +1-778-558-0447 (email info@gogreenmowing.ca). Good.
    - WARNING: search surfaces TWO other "Go Green"/"Little Green" lawn businesses
      in BC with different numbers (604-880-4355, 604-328-7326). Risk of
      misattributed reviews, confused customers, diluted citations in a crowded
      "[color] Green Mowing" micro-niche.
    - NO BBB listing found. YellowPages.ca search returns a DIFFERENT company
      ("Little Green Mowing Co"), not you.
    - Action: confirm GBP-verified phone (GBP always wins), make it byte-identical
      everywhere; claim BBB + a distinct YellowPages.ca listing.

[5] VERIFY THE GOOGLE BUSINESS PROFILE DIRECTLY (COULD NOT BE READ)
    The share.google link resolves to a JS-rendered Google Maps surface no
    automated tool in this session could read. Live rating, review count,
